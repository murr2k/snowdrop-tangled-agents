## 0  Caveat: data provenance

This waypoint's quantitative claims (cross-tabulations, the +0.891 max
SA score against AlphaQ, the 95.8% sign-agreement figure, the
1162 D / 235 L / 0 W summary, the oracle's 110-state reachable set,
etc.) are derived from `~/.tangled/game_stats.db` and from
`opponent_history` / `moves` data captured in games run before two
relevant strategy/instrumentation bugs were fixed:

- `8421c76` — *Remove failed_edges blacklist that incorrectly skewed strategy*.
  The agent was avoiding edges marked "failed", which biased the
  distribution of board states AlphaQ was asked to respond to.  Each
  individual opponent response is still valid (AlphaQ is deterministic),
  but the empirical state-coverage is non-uniform in a way the analysis
  does not correct for.

- `fa644f4` — *Fix interleaved move history: detect opponent moves at
  start of our turn*.  Before this fix, opponent moves could be
  misattributed to the wrong `state_after`, corrupting the mapping
  from board state to opponent response that the oracle and the
  forensic database queries depend on.

The high-level conclusions of this waypoint — H1 rejected, H2 (Nash)
supported, H3 (server-uses-SA) initially supported and later weakened
by §8 — are **independently corroborated** by the parallel work on
origin (`POST_SA_LUT_STRATEGY_OPTIONS.md`,
`EMPIRICAL_LUT_CONSTRUCTION_RESULTS.md`,
`PERSISTENT_EXPLOITABILITY_UNDER_EVALUATOR-POLICY_MISALIGNMENT.md`),
which use website-calibrated terminal scoring rather than the
move-history-derived oracle and so are not subject to the same
contamination.  The qualitative agreement between two methodologies
that fail in different ways is the main reason to treat the
conclusions as durable despite the source-data caveat.

The specific numbers in this waypoint should be read as
"directionally correct, magnitudes from possibly-tainted data."
A clean re-derivation against the post-fix portion of `game_stats.db`
is recommended before citing exact figures.

## 1  Summary

The Phase A "anti-correlation" finding is **incorrect as stated**.  Direct
inspection of `terminal_scores.mat` (which is Schrödinger ground truth, not
SA) and the full game database shows the Schrödinger LUT *correctly* predicts
wins for two of three opponents.  The genuine anomaly is that the LUT does
not predict wins for AlphaQ Up specifically — and this is consistent with
the Run 60–64 conclusion that the AlphaQ matchup is empirically Nash-solved
as a forced draw at +0.6 to +0.8.

The vertex-assignment hypothesis (LUT computed for wrong P1/P2 vertices)
is rejected.  Two hypotheses remain to test:

- **H2 (Nash):**  AlphaQ plays optimally as P2 and the matchup has no
  P1-winning continuation regardless of evaluator.
- **H3 (Server uses SA):**  Server adjudicates with simulated annealing.
  AlphaQ funnels into states where SA and Schrödinger disagree, draws
  under SA but wins under Schrödinger.

## 4  Experiment #1: Vertex mapping verification

**Question:** Does the LUT's `p1_node = 5, p2_node = 7` match what
the server uses when adjudicating AlphaQ matches?

**Result: Verified correct.**

### Code-level evidence
- `snowdrop_tangled_agents/strategy/petersen_strategy.py:72-73` — `MY_VERTEX = 5, OPP_VERTEX = 7`
- `snowdrop_tangled_agents/strategy/mcts_strategy.py:35-36` — same
- `snowdrop_tangled_agents/matlab/rl/generate_petersen_lut_schrodinger.m:41-42` — `p1_node = 5; p2_node = 7;`
- `snowdrop_tangled_agents/matlab/rl/TangledMCTS.m:77-79` — `P1_MY_EDGES = [10,11,12]` (1-indexed) which equals 0-indexed `[9,10,11]`, the edges touching vertex 5
- `snowdrop_tangled_agents/playing_games/run_local_parallel_tournament.py:157-158` — reads from engine's `graph_database`, not hardcoded; same values

### Website-level evidence
`play_tangled.py:469-479` documents the on-page vertex coordinates:

```
5: (80, 248),   # RED (us)
6: (451, 80),   # HUB
7: (820, 248),  # BLUE (opponent)
```

Edge list at `play_tangled.py:483-487` matches the LUT generator
byte-for-byte.

### Empirical evidence
If the vertex mapping were wrong, the LUT could not correctly predict
wins for any opponent.  It predicts them at 97% / 73% rates against
Amara and Melissa using the same agent and same conventions.  The
mapping must be correct.

## 5  Standing hypotheses and what would distinguish them

### H2: AlphaQ plays Nash equilibrium
- Predicts: no terminal state reachable from any opening will be
  classified as a server-win against AlphaQ.
- Already evidenced by 1,397 games with 0 wins, regardless of opening
  or strategy variant.
- ALPHAQ_SCHRODINGER_THOMPSON_RUN_ANALYSIS.md (Run 60-64) reached this
  conclusion explicitly.

### H3: Server adjudicates with SA, not Schrödinger
- Predicts: terminals where Schrödinger score is strongly positive but
  SA score is near zero or negative would be classified as draw or
  loss by the server, contradicting Schrödinger.
- AlphaQ data is consistent with this: by `final_score` (SA),
  positive SA → mostly draw (572D / 54L / 0W), negative SA → almost
  always loss (138L / 1D / 0W).  Zero wins at any SA value.
- vs Melissa, by contrast, positive SA does produce wins.

The two hypotheses are not mutually exclusive: AlphaQ may both play
optimally *and* the server may adjudicate with SA.  But they make
different predictions for novel terminals.

## 6  Disagreement search results (H3 essentially confirmed from existing data)

The database `final_score` field is the per-game SA score, so the
SA-vs-Schrödinger disagreement search did not require generating a new
LUT — it can be done directly against game history.

### 6.1  Sign-disagreement test

For terminal states reached in actual games where Schrödinger > +0.5
but SA < -0.5 (opposite signs, both magnitudes meaningful):

| Outcome | Count | Adjudicator implied |
|---|---:|---|
| WIN | 2 | Schrödinger |
| DRAW | 0 | (ambiguous) |
| LOSS | **46** | **SA** |

**Verdict: server outcomes correlate with SA in 95.8% of disagreement
cases** (n=48 games across 18 states).

The cleanest single example: terminal `PGPGGGPPGGPPGPG` was played 6
times vs AlphaQ.  Schrödinger says +7.94 (strong P1 win), SA says
**−8.81** (strong P2 win — opposite sign).  Server: 6/6 LOSSES.
SA wins.

### 6.2  Reachable-and-SA-positive terminals

Of the 110 oracle-reachable terminals:

- 61 have SA score data from played games
- 49 are novel (SA score unknown without offline computation)

The reachable terminal with the **highest known SA score** is
`PPPPGGGPPPGGPPG` at SA = **+0.861**.  It has been played 5 times
against AlphaQ and the server returned LOSS every time.  The
second-best reachable, `PGGGGPPGGPGGGPP` at SA = +0.779, has been
played 162 times against AlphaQ — all draws.

The 49 novel reachable terminals all have very small Schrödinger
scores (max +0.013), suggesting their SA scores are also small.
None of them are likely to be win candidates.

### 6.3  SA win threshold inference (from Melissa games)

Melissa win/draw/loss SA distributions:

| Result | n | SA min | SA max | SA avg | SA p25 |
|---|---:|---:|---:|---:|---:|
| Win | 329 | +0.035 | +15.365 | +2.268 | +1.092 |
| Draw | 568 | -2.064 | +1.746 | +0.297 | +0.045 |
| Loss | 652 | -7.300 | +2.681 | +0.037 | -0.058 |

Lowest-SA recorded win vs Melissa: **+0.035**.  Highest-SA recorded
draw: +1.746.  There is massive class overlap, so SA alone is not a
clean predictor — but the **median win SA (+2.27)** is well above
anything ever reached against AlphaQ.

The maximum SA score we have ever achieved against AlphaQ in 1,397
games is **+0.891**.  That terminal was a LOSS five times.  AlphaQ
constrains us to states where SA is too low to win.

## 7  Updated experimental plan

### Conclusions consolidated

- **H1 (vertex mismatch): rejected.**  Mapping verified correct.
- **H3 (server uses SA): supported at 95.8% confidence** by existing
  game-history data.  No new experiment was needed to confirm this —
  the database already contained the answer.
- **H2 (AlphaQ plays Nash): strongly supported** by the gap between
  achievable SA score (+0.891) and the SA win threshold (~+1.0–+2.0).
  AlphaQ funnels every line to weak-SA terminals.
- The Schrödinger LUT and the minimax-over-Schrödinger expanded LUT
  are optimizing the **wrong objective** for server agreement.

### What experiment #2 should now be

The original framing — "find a single Schrödinger-vs-SA disagreement
state and play it" — has been answered preemptively by the data.  The
right next experiment is:

**Experiment #2 (revised): full SA LUT generation + win-set enumeration.**

1. Generate `terminal_scores_sa.mat` for all 32,768 Petersen terminals
   using `generate_terminal_lut.py --graph 5 --scorer simulated_annealing`
   (~27 minutes single-core, less in parallel).
2. Identify the **win set**: terminals with SA score above the
   Melissa-derived win threshold (e.g., > +1.5 for confident wins).
3. Cross-reference with the oracle reachable set.  Find the reachable
   subset of the win set, if any.
4. If empty: H2 is mathematically confirmed for the explored game tree.
   AlphaQ has no off-Nash line we can exploit through oracle-known
   territory.
5. If non-empty: a single hard-scripted game will tell us if AlphaQ
   actually allows that path or has an unobserved deviation.
6. If empty under oracle but the unexplored portion of the game tree
   still contains win-set states: targeted exploratory games to
   expand the oracle in regions adjacent to the win set.

### Cost vs payoff

| Step | Cost | Information gained |
|---|---|---|
| Generate SA LUT | ~30 min compute | Definitive answer to "do reachable SA-wins exist?" |
| Cross with oracle | seconds | Concrete state list, or empty |
| Forced-game test | 5–10 games (~30 min) | Empirical confirmation of any candidate |

This replaces both the original Phase B (calibrate outcome model) and
the Phase A oracle gap-filling, because if no reachable SA-win exists,
neither approach can produce wins.

## 8  Experiment #2 results (executed 2026-05-07/08)

### 8.1  SA LUT generation

The full SA LUT was generated using
`generate_terminal_lut.py --graph 5 --scorer simulated_annealing
--output terminal_scores_sa.mat --workers 8`.

Runtime: 51.9 minutes (95 ms/state effective with 8 parallel workers,
100,000 reads each).  Output:
`snowdrop_tangled_agents/matlab/rl/data/terminal_scores_sa.mat`.

### 8.2  Full-LUT SA distribution

| Bucket | Count | % |
|---|---:|---:|
| Confident P1 wins (SA ≥ +1.99) | 5,590 | 17.06% |
| Marginal P1 wins (SA ≥ +1.09)  | 7,475 | 22.81% |
| Confident P2 wins (SA ≤ −1.99) | 5,588 | 17.05% |

So winning terminals exist in abundance — about one in six is a clear
P1-win under SA.  The question is whether any are reachable.

### 8.3  Reachable subset

| Set | Count |
|---|---:|
| Oracle-reachable terminals (Phase A) | 110 |
| Above marginal SA win threshold (≥ +1.09) | 16 |
| Above confident SA win threshold (≥ +1.99) | 4 |
| **Of which novel (never tested)** | **0** |

Top-4 confident-win-threshold candidates, all already tested:

| State | SA | Schröd | History vs AlphaQ |
|---|---:|---:|---|
| `PGPGGGPPPGPGGPG` | +2.79 | +3.97 | 3 LOSSES |
| `PGPGGGPPGGPPGPG` | +2.58 | +7.94 | 6 LOSSES |
| `PGPGGPPPPPPGGPG` | +2.49 | +3.97 | 7 LOSSES |
| `PPPGPPGGPPGPGPP` | +2.19 | +3.98 | 8 DRAWS |

### 8.4  H3 weakened, H2 confirmed within explored tree

The result actually **weakens H3**, not strengthens it.  Section 6
established that the server agrees with SA in 95.8% of opposite-sign
disagreement cases.  But these new candidates show SA strongly positive
(+2.19 to +2.79, well above Melissa's empirical +1.99 win-median) yet
the server consistently scores them as draws or losses — **never wins**.

A pure-SA server would have produced wins for `PGPGGGPPPGPGGPG`
(SA = +2.79) at least some of the time across the 3 games where it
appeared.  None occurred.  So the server adjudicator is **either**:

- Not pure SA: possibly real D-Wave hardware, lower-read SA, or a
  noisy variant where SA-positive states sometimes flip to non-wins.
- Or pure SA but with parameters we can't replicate offline (anneal
  time, num_reads, embedding) that makes its scoring less generous
  than our 100K-read offline LUT.

For the strategic question — "can we beat AlphaQ?" — the conclusion
is firm regardless of which is true.

**H2 (Nash within explored tree): mathematically confirmed.**  Among
the 110 oracle-reachable terminals, there is no novel candidate that
exceeds the SA win threshold.  The 16 marginal candidates that do
exceed it have been tested 24+ times across them and produced 0 wins.
The matchup is solved as a draw within the explored game tree.

### 8.5  What this leaves

Two paths remain, both with low expected payoff:

1. **Oracle gap-filling.**  The current oracle has 9,339 gaps where
   AlphaQ's response is unknown.  Targeted exploratory games could
   discover a previously-unobserved AlphaQ deviation that opens a
   line to a novel SA-positive terminal.  Given 1,397 games haven't
   found such a deviation, the prior probability is low.

2. **Server adjudicator reverse-engineering.**  If the gap between
   our offline SA and the server's adjudication is consistent and
   modelable, we could build a calibration curve mapping (SA, other
   features) → P(server-win) and target only the high-probability
   states.  Effectively the original Phase B, but with the realisation
   that pure SA is also insufficient.

### 8.6  Recommendation

Accept the Nash equilibrium as the project's empirical achievement.
The Run 64 result (100% draw rate, +0.779 average) appears to be the
true ceiling for this matchup.  Further investment in MCTS depth, LUT
quality, or oracle expansion is unlikely to break the draw, because
the bottleneck is AlphaQ's near-optimal play — not our search or
evaluator.

Redirecting compute toward weaker opponents (Melissa, Amara, the
X-Prize bounty graphs) where wins remain achievable is likely a
better use of resources.

The investigation produced three coexisting LUT files in
`snowdrop_tangled_agents/matlab/rl/data/`.  All three are kept for
reference and reproducibility.

| File | Adjudicator | Generated | Purpose |
|---|---|---|---|
| `terminal_scores.mat` | Schrödinger ground truth | 2026-02-01 (preserved) | Live MCTS terminal evaluator. **DO NOT replace.** This is what `score_terminals.py`, `TangledMCTS.m`, and the Schrödinger-based expanded_lut all expect to find. |
| `terminal_scores_schrodinger.mat` | Schrödinger ground truth | 2026-05-07 (backup copy) | Identical to `terminal_scores.mat`.  Created as a safety backup before the SA generation run.  Can be deleted if disk space matters; otherwise keep as a redundant copy. |
| `terminal_scores_sa.mat` | Simulated annealing, 100K reads | 2026-05-07/08 | Used by `find_sa_win_set.py` and any future analysis that needs SA-aligned scores.  **Do not** load this from MCTS code expecting "the LUT" — it has different sign behavior in disagreement cases. |

`generate_terminal_lut.py` was extended with an `--output` flag during
this investigation so additional LUT variants can be generated without
clobbering the live one.  Default output remains `terminal_scores.mat`
for backward compatibility.

`snowdrop_tangled_agents/oracle/data/sa_win_candidates.json`, produced
by `find_sa_win_set.py`.
